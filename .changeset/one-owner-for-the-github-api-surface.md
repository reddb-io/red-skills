The decision of which GitHub API answers a call now belongs to one package, `@reddb-io/github`, and it is made by cardinality. `ghReadSurface` already knew the answer for every call and spent that knowledge labelling failures; nothing routed on it, and its default sent everything that was not `gh api <path>` to GraphQL. So the hot path — one issue or one pull request read by number, polled per Worker per iteration — was single-object reads issued against the pool metered by node points. Measured twice within one hour on one machine: GraphQL at `0/5000` while REST sat untouched at `4891/5000`, and the drain stalled both times. A single-object read now goes to REST and a multi-node listing or multi-repository aggregate to GraphQL; `surfaceForCardinality` is the whole rule, and a read entry that states anything else fails the table's own assertion. The one class of exception is declared rather than silent: Actions runs, Releases and the search endpoints are exposed by exactly one API, so there is no routing choice to make and the entry says so. Writes are observed rather than chosen — `gh issue comment` is a REST POST and `gh issue create` a GraphQL mutation — which stops a REST-metered write from reporting a GraphQL quota failure. An operation matching no entry now raises and names the key it derived instead of inheriting whichever pool the old default happened to pick, and a test pins the table so a surface change has to edit it on purpose. Deciding a read belongs on REST changes nothing until it is issued there, so the package also carries the realization: the `gh api repos/{o}/{r}/issues/{n}` argv plus the projection back into the shape `--json` would have printed. The claim pre-check, the orphan and blocker sweeps, the branch-cleanup lookup, the issue-reference reads and the merge-queue confirmation all take it. A field with no single-request REST equivalent is named, not approximated — `comments` is a count in REST and a list in GraphQL, `statusCheckRollup` is two further requests — and those reads keep gh's own command with the gap recorded. The daemon's multi-repository activity poll derives its endpoint from the same table instead of hardcoding one next to it, and the castle's tracker adapter imports the same module, because two implementations of one routing rule drift.
