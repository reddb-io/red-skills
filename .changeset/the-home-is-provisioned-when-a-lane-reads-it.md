The host-scoped home is now **provisioned when a workspace lane actually reads it, and never otherwise** (#2958). Getting a working `redskilled` read as "run `/red-setup`, which provisions `~/.red/redskilled/`, then the daemon can run", and two of those three steps were not true. The daemon never touches the home: it binds its socket and writes its lease and event lane under the session runtime dir, and resolves the home nowhere. And start is already auto-spawn (ADR 0130 rule 7), so the first client reaching an absent socket brings a daemon up with no `provision` in between. What was left was a directory created once and never written — on a machine running the daemon for a day, empty — with an interactive installer sitting on the critical path of a daemon it was not a precondition for.

Exactly one thing reads the home: a Worker workspace lane rooted inside it — the `host` preset, or a custom parent under the home. `workspaceReadsRedskilledHome` names that in the layer that already names the lane, and `readRedskilledHomeNeed` turns a repository's declaration into the need plus **the declaration that decided it**, so `redskilled provision` reports `needed_by` on every run rather than leaving an operator to guess why a directory is absent or empty. `--workspace host` states the target outright, which is the moment a preset is selected; `--project <dir>` names the repository whose config declares it. **`provisionRedskilledHome` remains the ONE creator (ADR 0130 Amendment 2)** — this changes *when* it is called, never *who* calls it.

An absent home is two states, and reporting them as one was the defect. `/red-doctor` now distinguishes **absent-and-unneeded** — `ok`, with the declaration that says so — from **absent-and-needed**, which stays a `missing` finding naming the target that needs it. A row that reddened over an unneeded absence sent operators to cure a machine that already worked, which is the one thing a doctor cannot afford to teach.
