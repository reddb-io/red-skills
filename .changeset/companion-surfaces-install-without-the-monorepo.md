Both companion surfaces that read the `redskilled` daemon are now installable without this monorepo. `red-publish` packages the VS Code extension and attaches `vscode-extension-red-skills-<version>.vsix` to every GitHub Release, stamped with that release's version inside the archive as well as in its name — an editor keys "already installed" off the manifest, so a static version would have made every release after the first a download nothing installs. The extension still reaches no marketplace; that refusal was about pushing to a destination this repo does not have, and a release asset is the opposite shape. The herdr plugin gains the repo's own dist-bundle step: one esbuild file with `@reddb-io/toon` and `@reddb-io/build-info` inlined, attached to every Release, which its install-time build hook downloads and writes over its entry. `herdr plugin install reddb-io/red-skills/apps/herdr-plugin-red-skills` therefore works on a machine with no checkout and no `pnpm`, where it previously completed and then failed at the first import of a workspace link that was never downloaded with it; `herdr plugin link` stays the contributor path, and a linked checkout materializes nothing. The detached watcher now re-execs the entry that is running rather than one derived from a module's own URL, which named a path outside the plugin root once that entry was the bundle. Both READMEs lead with the download-and-install commands for VS Code and VSCodium, and demote building from source to the contributor path.
