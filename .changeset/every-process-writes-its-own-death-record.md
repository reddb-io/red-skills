Every process that CAN say goodbye now does. A launcher, a worker and the host daemon each write one death record on every trap-able exit — the signal or the exit code, the last phase the process had announced, and its rusage — into a TOONL lane under the durable state root (`.red/state/deaths/deaths.toonl` for a checkout, `~/.red/redskilled/state/…` for the daemon). The dying process is the writer, so no watcher is required: a record that needed a live parent to observe the exit would be absent in exactly the case that matters most, the one where the parent died too. One shape covers all three writers, so a reader joins deaths across process classes from one decoder, and `signal`/`exit_code`/`last_phase` are carried structurally rather than folded into prose nobody can parse next year. Exactly one record per process life: a delivered signal latches, so the exit that follows never overwrites the reason with the code the runtime happened to reach, and a clean exit stays distinguishable from a kill. `markProcessSafetyStep` now announces to both records at once, so `last_phase` is the phase the process was actually in. Un-trap-able deaths remain out of scope by design — a SIGKILL fires no handler, and its missing record is the signal a later reaper attributes from kernel evidence.
