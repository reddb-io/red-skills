A version is a cache key, so a key that can be empty is now refused rather than spelled. The daemon's self-healing rung passed `version: io.version ?? ""` into `ensureBundle`, and nothing anywhere resolved `""` to the newest stable — the empty string travelled all the way to the filename and minted `redskilled-.bundle.min.mjs`, a name no resolver prefers. Worse, `companionBundlePlugins("redskilled")` is `[]`, so the cache-first test reduced to "does this file exist", and once it did, that rung returned early forever, on every version and every boot. **The rung that exists to heal a host with no daemon bundle wrote the one artifact guaranteeing it would never heal again.** `bundleFileName` now raises `invalid-version` where the name is minted rather than at each caller, because the next caller will spell absent its own way; the daemon resolves its version from the `dev` bundle beside it in the cache (same npm package, no network) and falls back to the registry's newest stable; a host already holding the unversioned entry fetches anyway and the entry is moved out of the `<plugin>*.bundle.min.mjs` glob on the next success, because a fix that only prevents new ones repairs neither reporting host.

The other half is that a fix shipping in the bundle lane cannot repair the lane that fetches bundles. #3074 made `redskilled` a companion of the `dev` warm path, and the checked-in `plugins/dev/hooks/red-fetch.mjs` — the esbuild artifact the SessionStart hook actually executes — was never rebuilt, so every published version kept answering `["rsp"]` and the daemon bundle was warmed on no host at any release. The artifact is rebuilt, a ratchet reads the companion set out of the shipped bytes so a source-only edit fails the gate, and `red-doctor` gains a warm-path check that asks the INSTALLED fetcher what it knows to warm — by substring over its bytes, never by importing it, since the point is what the older copy believes. An unreadable warm path reports `unknown`, never `complete`.
