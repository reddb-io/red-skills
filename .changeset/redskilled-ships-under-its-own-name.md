`redskilled` now ships under its own name, and runs out of a clone (#2960). The daemon was reachable only as `red-skills-redskilled`, so the shortest route to the host's state was `npx -y -p @reddb-io/red-skills@latest red-skills-redskilled host-state` — a prefixed name nobody guesses, for a product whose own name is `redskilled`. Both `npx -y @reddb-io/red-skills@latest redskilled …` and `./bin/redskilled …` now work. **This adds, it does not rename**: `red-skills-redskilled` keeps working unchanged, and there is precedent in the very same `bin` map — `rsp` already ships bare, because a bare name is what this repository does when the name is the product's own.

**The alias is ergonomics, not a new dispatch contract, and the docs say which is which.** ADR 0091 made `npx -y -p <pkg>@<version> <bin>` canonical precisely because a bare shim resolved off `PATH` can pick up a *different* installation than the one intended (PR #2465). Adding a bare bin must not weaken that, so the pinned form stays canonical — the self-replacement's own successor lookup still builds it — and the bare name is documented as the shorter way to say the same thing. Both bins exec the one `dist/redskilled.bundle.min.mjs` and forward argv whole, so `--version` answers identically whichever name is typed; the pre-publish pack check now asks both and fails on any difference, which is the regression an alias can quietly introduce.

**The clone route exists for a different reason: a registry fetch must not stand between an operator and the binary that reports what is broken.** `./bin/redskilled` resolves the checkout from its own path rather than the cwd — an absolute-path run from inside the broken project reaches this checkout, not that one — and takes the built `dist/` artifact when there is one, the workspace TypeScript runner over `apps/redskilled/src/cli.ts` otherwise. With neither present it refuses and names both routes plus the published binary, rather than dying deeper on a module resolution error: the same fail-closed posture ADR 0130 rule 6 gives the daemon's own spawn.

`isRedskilledEntryPath` now recognizes both bare spellings and the extensionless launcher, so a spawn whose caller entry is one of them knows it is already standing on the front door instead of hunting for a sibling bundle. The names are matched whole — `redskilled-helper.mjs` is a different file that happens to start with the same word.
