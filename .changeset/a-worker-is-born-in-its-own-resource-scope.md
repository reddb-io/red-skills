Every Worker the host daemon births now runs in its own resource scope under a stated memory ceiling, and no new knob states it: the ceiling is derived from the accounting the daemon already keeps — the host memory ceiling shared across its declared Worker slots, capped at the headroom the live Workers' own budgets leave — and carried into the transient unit as `MemoryMax` (a Job Object's limit on Windows). A client that declared its own budget is never narrowed. The derived number is a wall, not memory set aside: it deliberately stays out of the admission charge, so one Worker cannot spend the whole host accounting and have every Worker after it refused. Host memory pressure now kills the Worker that earned it instead of the terminal's biggest bystander, and the kill is attributable because the scope names the Worker. The placement is handed down to the Worker itself (`RED_WORKER_SCOPE`, `RED_WORKER_MEMORY_CEILING`, `RED_WORKER_SCOPE_DEGRADATION`) and lands on the death record it writes on the way out, so a post-mortem reads what contained the process and under what ceiling. A host with no systemd still launches and still has a ceiling — the daemon's RSS sampling floor now enforces the derived one too — with the degradation NAMED on the reply, in host state, and on the dead Worker's own record rather than inferred from an absent scope.
