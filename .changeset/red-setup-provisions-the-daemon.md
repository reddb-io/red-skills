`/red-setup` provisions the execution daemon, so a fresh machine has a route to a working `redskilled` (#2853). The string `redskilled` appeared nowhere in the setup skill or its command: nothing created the daemon's home, nothing declared it, and a machine with no prior state had no path to a reachable daemon at all. The home also sat between two records — ADR 0067 makes `/red-setup` the sole creator of `.red/`, while `~/.red/redskilled/` is operator-scoped and outside every checkout — so it had no owner and was one accidental `mkdir` away from having several. **ADR 0130 Amendment 1 settles it: the home belongs to `redskilled`.** `provisionRedskilledHome` (`apps/redskilled/src/provision.ts`) is the ONE creator, every other surface reads the single namer in `packages/shared/redskilled-home.ts`, and ADR 0067's authority is now explicitly repository-scoped. The daemon owns it because start is auto-spawn (rule 7): a home only an interactive installer could create would leave a fresh machine failing closed forever, with the daemon depending on the tool that depends on the daemon. Setup gains a caller's job instead — Section E3 runs `redskilled provision`, which creates the home owner-only (`0700`), starts the daemon through the ordinary client path, and prints a TOON audit. **Idempotent by construction**: an existing home keeps everything in it, and the only thing a second run can change is a permission bit that drifted wider than owner-only — a repair, not a rewrite — which is what makes it safe to run on every setup pass rather than only when something already looks wrong. The same section offers the optional supervising user unit (`Restart=on-failure` over the identical binary, socket and contract — still one behaviour with a supervisor, never a second spawn path), written only when absent so an operator's edited unit is never rewritten. `/red-doctor` gains check 24, rendering the same four checks — `home`, `daemon-entry` (naming every probed path when no published bundle resolves), `reach`, `supervisor-unit` — from the same pure audit over injected facts, and it probes the socket **without ever spawning** the daemon it reports on, because a report that started the daemon would answer its own question. The optional unit is reported and never flagged: an absent unit is `ok` with a stated absence, since a doctor that reddens over an optional thing teaches operators to ignore a red row.
