Every surface now answers "why did it die" and "is my engine current" without a second read. The verdicts the boot reaper poses (#3028) exist for a moment in exactly one process — it clears the anchors it read — so `redskilled serve` hands them to the daemon rather than dropping them on stderr, and the statusline payload carries them from there. The aggregate that already fed the statusline, the herdr pane and the VSCode panel gains two optional blocks: `deaths`, each verdict reduced to who ended it, how sure the reaper is and the one fact the verdict rests on; and `engine`, which states the running version and the resolved published one side by side rather than folding them into a single confident number. The statusline head carries `v<version>` and `†<n> <class>` at every detail level, because "what version is answering" is the first fact a skew investigation needs and a version that only survived on a wide terminal is absent exactly when the line has already degraded. The dashboard header repeats the badge for the status bar that shows it alone, and prints one receipt line per verdict below the Workers — naming a process that is in no Worker row, which is precisely the reader a table cannot answer for. Absence keeps its meaning end to end: a daemon that never reaped leaves the block absent, an empty reaping is a real answer with a count of zero, and neither renders as `†0`. Both blocks are optional on the wire (ADR 0130 rule 3), so an older daemon still serves a complete payload and a newer client draws no calm zero in place of what it was not told.
