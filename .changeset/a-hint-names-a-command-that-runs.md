Every doc surface and every code-emitted operator hint now names a command that actually runs. Our binaries are not on an operator's PATH, and where a shim exists it may be a stale pin, so the canonical invocation is the npm direct-run form that pins the version and works on every installation — yet the root README, a dozen SKILL.md files and the app READMEs all offered `redskilled provision` and `red-skills-dev …` bare, as if a shim were a given. The runtime hints were worse: the birth refusal, the registration refusal and the provisioning audit each told a stuck operator to run `redskilled provision` at exactly the moment that binary provably was not resolvable — an instruction pointing at its own precondition, the dead-end shape the entry-fetch rung was added to close. All of them, plus the VS Code extension's absent-daemon tooltip and empty-state panel and the daemon's own major-hold action, now spell the canonical form through one namer rather than four hand-written spellings that drift into four different repairs. A PATH shim is stated as what it is, a warm-cache optimization, and the two legitimate exceptions stay and are declared: contributor docs running from a checkout, and `rsp`, a repo-local surface by design. A guard sweeps the root README, `docs/`, every plugin's skills tree, the app READMEs and the generated packaging mirrors, and runs in every gate run rather than only a whole-workspace one, so the next doc regresses red instead of silently; its whole discrimination is "binary token followed by another token", because naming a binary is prose and a line somebody pastes is not.
