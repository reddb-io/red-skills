There is exactly one `redskilled` per machine, and the scope is now enforced rather than asserted (#2885). ADR 0130 said "one daemon per user session" and `paths.ts` argued the rejected alternative in its header — keying on the host would be "wrong the moment an operator has two logged-in sessions". The premise was wrong: `XDG_RUNTIME_DIR` is per **user**, not per login, so every terminal of one operator already resolved to the same `/run/user/<uid>` and the same daemon. The one case the old wording never covered is two different OS users on one machine, whose runtime directories are `0700` against each other — neither daemon can see the other, and the machine ends up with two arbiters and no error. A second daemon does not degrade the host budget, it **voids** it, because each one is correct about a total that is not the machine's.

**The multi-user case is decided in code, and the decision is refusal.** A world-readable machine claim — one TOON record written `wx` in a shared sticky directory (`$TMPDIR/redskilled-<machineIdHash>`, `%PROGRAMDATA%` on Windows) — names the daemon that holds the machine, and a session that finds a live holder elsewhere refuses to start, naming the pid, uid and socket that hold it. Serving a second user from the first user's daemon would run every one of their Workers as the first user; widening the socket to `0666` is the same crossing with the kernel's help. The claim joins the exclusive bind and the session lease rather than replacing either: the bind owns "who has the socket now", the lease owns "who has this runtime directory across restarts", and the claim owns the question neither can see. A claim is a daemon's own only when pid, start instant **and** socket path all match, so one process cannot admit itself twice, and a dead claim it may not unlink ends in a stated refusal instead of an opening — a directory full of corpses never lets the next daemon believe it is the first.

`host-state` now carries a `scope` block — kind, claim path, owner uid, machine and session digests, socket — so an operator reads the scope the daemon believes it holds instead of trusting a comment, and `REDSKILLED_MACHINE_DIR` pins the claim directory outright for an operator who must state it. ADR 0130 Amendment 2 records the decision, and the `paths.ts` header no longer argues for the superseded scope.
