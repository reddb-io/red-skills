The default fleet width is one, and one namer says so. The number lived in three places that disagreed: the MCP `project_start` schema defaulted to `2`, `CONFIG_DEFAULTS` carried `"2"`, the AFK configuration documentation had no width row at all, and the maintainer's intent was `1` — three surfaces announcing different numbers are three defaults, and the drift stays invisible until somebody counts running Workers. `packages/shared/default-fleet-width.ts` is now the single declaration both the schema and `CONFIG_DEFAULTS` read, the docs gained the row an operator looks for, and a test fails when any of them disagree — verified red-first by putting `2` back in the schema. One rather than two because a second Worker doubles GitHub polling against a budget metered per token (two spend roughly 2200 GraphQL points an hour of a 5000/hour window) and doubles memory against a host ceiling every Worker is already granted in full, which is worth choosing deliberately rather than inheriting; a project that wants more states it in `plugins.dev.afk.target`, bounded from above by the daemon's host-scoped ceiling, because width is machine budget rather than project preference. `packages/red-castle` gained the `@reddb-io/shared` dependency it had been importing without declaring.
