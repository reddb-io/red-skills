The `redskilled` daemon now adopts a newer published bundle while it is WORKING, and says whether it ever looked. A daemon holding a registration never goes idle — the registration is what keeps it alive, so a drain outlives the session that started it — which made the idle-boundary check unreachable on exactly the hosts with work to do, leaving the fifteen-minute interval as their only route. That interval also cannot say anything for a daemon's first fifteen minutes, so a release published into that window was served past with no check having run at all. The daemon now takes one look shortly after boot as well, a successor is owed no boot look so a mis-resolving one cannot restart itself in a loop, and a live Worker is carried through either route untouched — a replacement is a restart, not an evacuation. A local build is refused on every route before the read is spent, rather than at the idle boundary alone. Host state gained `upgrade.checks` and `upgrade.hold_reason`, because "the check never fired" and "it fired and held" reported the same null published version and are different defects with different cures. A published read that runs out of time now falls back to what the host already holds, exactly as a read that throws always did: a slow registry must not erase the newer bundle sitting in the cache.
