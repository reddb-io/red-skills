Every workspace in the monorepo now carries one product version, and every publishable surface reports it. Eleven packages were aligned and ten were not: the `ignore` array in the changesets config held eight of them, so the release train deliberately left them behind, and the herdr plugin was in neither `fixed` nor `ignore` — in no list at all — so it drifted eleven patch releases on its own. The two visible casualties were the surfaces an outsider actually reads: the VS Code extension shipped every release stamped `0.1.0`, the field the marketplace and the `.vsix` key "already installed" off, and the herdr plugin manifest sat at `0.1.0` while its own package said `0.1.11`, two numbers nothing compared. Nothing was red, because alignment was maintained by a hand-kept list and a hand-kept list is exactly what a new package is absent from. `ignore` is now empty, every workspace member rides the `fixed` group, and the version-sync script — which propagates the changesets-decided number to the files outside the pnpm workspace — reaches the plugin definitions, the extension manifest, and the herdr plugin's two non-JSON sites, its install manifest and the entry's checkout fallback constant. The binaries' `--version` answers are untouched: they were always right, read off the build stamp, which is why the daemon reported the product version while its package said `0.1.0`. A ratchet now derives the package set FROM the pnpm workspace globs rather than from an array anyone maintains, so a new app inherits the obligation the moment its `package.json` lands, and it fails three ways: a manifest off the product version, a manifest no release train writes (aligned-by-luck is not aligned), and a workspace named outside the `@reddb-io` scope. Two scope exemptions are stated with the reason the scope cannot be spelled there — the pnpm root, which is unscoped by convention and whose scoped name is already another package, and the VS Code extension, whose `name` must match what `vsce` accepts and whose ownership claim is its `reddb-io` publisher.
