The dead code a reachability sweep proved has no reader is gone. A scout traced the import graph from every package's `bin`, `main` and `exports` map and cross-checked it by grep (#3021); this lands the half of that report where nothing — not source, not a test, not a doc, not CI, not a manifest — reads the thing. Four modules go: `removed-fleet-flag` (the Fleet's migration answer, written and never wired into the CLI that would refuse a stale `--fleet`), `supervisor-exit` (an exit recorder nobody records through, whose only repo-wide namesake is an unrelated string literal in the daemon's self-replacement union), the `config-namespacing` probe (absent from both the probe barrel and the registry, so it never ran once — while boot dutifully computed its input every launch and handed it to nobody), and red-castle's `sandboxExec` (no consumer in the fork, no tsup entry, no `exports` entry). Nothing is lost with the probe: the *registered* `config-coherence` probe already receives the same facts and already reports every root accessor collision with its canonical key.

Three test files come back to life rather than dying. They sat under `apps/dev/src/`, where the vitest config's `tests/**/*.test.ts` include never reached them, so 385 LOC had asserted nothing since the day they landed while reading in review exactly like real coverage. Each covers a live module with no other unit test, so each moved into `tests/` — 19 tests now run and pass on their first real execution. A new guard fails on any future `*.test.ts` under `apps/dev/src/`, and it stays a package-local check rather than a repo-wide invariant because the same colocated layout is *correct* in `packages/red-castle`, whose config collects it.

Also swept: two re-export shims whose only readers were tests that can import `@reddb-io/red-castle/engine` directly, four dependencies declared and never imported (`@effect/printer`, `@effect/printer-ansi`, `vscode-jsonrpc`, `@reddb-io/toon` — `@types/vscode` stays, it is ambient), and three dead script entries (`release:tag`, whose work the ADR 0121 tag-cutter does; the `release:manifest` alias the publish workflow bypasses by calling the script directly; and a fixture harness no workflow has ever run). The printers earned a second look and survived it: they are peer dependencies of `@effect/cli`, and pnpm still satisfies them inside that package's own tree, so dropping red-castle's unused direct declaration starves nothing.
