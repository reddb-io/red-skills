`redskilled` supervises its own life: an optional user unit revives it, and it adopts a newly published bundle (#2852). Both halves of the daemon's life were missing and they are one question. **Supervision**: ADR 0130 rule 7 chose auto-spawn as the floor *plus* a user unit with `Restart=on-failure`, and only the floor shipped — so a daemon that died mid-flight came back when some client next happened to want work, on the one component whose absence stops every project on the machine. `redskilled unit install|uninstall|status` now writes, enables and removes that unit, and its `ExecStart` is built by the same argv builder a client spawn uses (`redskilledServeArgv`), so a flag can never reach one start path and miss the other. A host that never installs it is a supported configuration and says so (`floor: "auto-spawn"`); the binary, the socket and the contract are identical either way. **Upgrade**: nothing in the daemon resolved the published version or replaced itself, so publishing a release left the singleton serving old code indefinitely — the failure that killed 21 Workers in 20 minutes one layer up (#2808), with a wider blast radius here because every project shares this process. The daemon now resolves the published version on its own tick, and when a newer one exists it finds a successor that runs *exactly that version* (bundle cache, the bundle beside its own entry, then a version-pinned dispatch), flushes the event lane, releases the socket and the lease, and starts it — or, under a supervisor, exits non-zero so `Restart=on-failure` starts it. Workers are init-system units, so the swap is a restart and not an evacuation: the successor re-adopts every live Worker off the lane, and a published bundle this host cannot reach costs the upgrade and nothing else, because the successor is resolved *before* anything is given up. The published answer travels beside the running one (`upgrade.published_version` next to `daemon_version`) and an unresolvable read stays `published_unknown` rather than becoming a match, so the daemon never reports a version it is not running.
