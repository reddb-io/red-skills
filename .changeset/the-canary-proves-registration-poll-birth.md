The canary walks registration → poll → birth on the shipped artifacts (#2908). The MCP lane canary stopped one step after the two-player model begins: it proved a project could register and that registering started no process of the project's own, and then went home. From the project's side, a lane that registers and then does nothing forever looks exactly like a lane that drains — the difference lives inside the daemon — so every regression past the registration was invisible to the one probe that runs against what ships.

**The walk now asks the daemon directly.** Two steps join the lane. `queue_polled` waits for the poll that covers this project and reads its cost, because ADR 0130 Amendment 3's whole claim is that N projects cost ONE aliased request and a depth that arrived at per-project cost is the shape the batching replaced. `worker_born` waits for the Worker that poll justified, read back from the host and cross-checked against the machine, because a pid file cannot say whether a birth was ever admitted. `no_project_process` changed with them: a live Worker in the lane is no longer a fault by itself — the daemon births one there now — so what is read is **parentage**, and a worker the host does not name is the unadmitted, uncounted, unstoppable birth the step always existed to catch.

**`host-state` reports the last poll per registration**, carrying the poll's instant, its outcome, its depth and what the whole interval cost. An absent block means nobody has counted this project yet, which is a different answer from a depth of zero and sends an operator somewhere else; a spent quota still carries no depth, never the zero that would retire a project which still has work.

**`redskilled serve` arms the loop it was given.** The queue poller and the demand window were daemon options nothing on the shipped path ever set, so a machine running the real binary held registrations, counted no queue and birthed nothing while every in-process test of the loop stayed green. `serve` now takes `--queue-endpoint`, `--queue-ms` and `--demand-ms`, and arms the poller from one host token; with no token it holds registrations and counts no queue, which is an honest unknown and never a drained one. `project_stop` ends this project's Workers through the daemon before giving the registration back, so work nobody is watching cannot outlive the record that asked for it.
