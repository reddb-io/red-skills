The deaths nothing could record now get a verdict. A SIGKILL fires no handler, and a machine freeze erases the memory of itself, so the death record #3023 guarantees is simply absent — and that absence is now the evidence. Every process that installs a death recorder also drops a presence ANCHOR (`.red/state/deaths/live/<kind>-<id>-<pid>.toon`, refreshed on every phase and removed the instant a real record lands), so an anchor still on disk at the next boot means exactly one thing: a process left without saying how. Nothing has to be watching for that to work, which is the point — a watcher is the first thing a freeze kills. At boot the reaper joins the anchors against the death lane and the host's own memory — `/proc`'s boot id and live pid set, the kernel/journal tail, the cgroup and the parent account — and writes one verdict per un-recorded death to `.red/state/deaths/attributions.toonl`, naming its sender class (`oomd`, `user-signal`, `parent-death`, `teardown`, `unknown`), its confidence, and the evidence it used. Specific beats general: a line naming the pid beats one naming its cgroup scope, which beats one naming only the host, and a boot boundary demotes any pid-keyed match because pids are reused across boots. An honestly unknown cause is reported as `unknown` with the list of everything consulted and what each source answered, because "we do not know, and here is where we looked" is a finding while an invented cause outlives the incident. The project boot sweeps and the host daemon each run the reaper before anything that can fail on the network. Attribution is proven on a POSED host: injected `/proc` trees and journal files drive the shipped collector, the way WSL2 support was proven, so no fake evidence object stands in for the code an operator runs.
