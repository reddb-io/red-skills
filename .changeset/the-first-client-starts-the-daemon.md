The first client reaching an absent socket starts `redskilled`, from the published bundle (#2843). Nothing spawned the daemon at all: no process, no socket, and a client path that assumed a listener which never appeared, so every consumer of host-scoped truth silently got nothing. Reaching an absent socket now starts the daemon and completes the original request without the caller retrying, and the start stays idempotent under concurrency — the spawn lock plus the daemon's exclusive bind converge N racing clients on one daemon, and the loser joins the winner instead of failing. The spawn resolves the daemon entry by name (`src/daemon-entry.ts`: `REDSKILLED_BIN`, the caller's entry only when it is itself a redskilled entry, the bundle shipped beside a host, the repo `dist/`, the workspace, the installed package, the bundle cache) and **never re-executes the calling process's own entry path** — the defect already fixed twice here (#2736 in the rsp resident, #2677 in the fleet launcher), whose signature is that the launcher's version becomes the daemon's, so a stale caller quietly mints a staler daemon and the skew widens instead of clearing. A bundle that cannot be resolved is `RedskilledDaemonEntryError`, naming the caller that asked and every path probed, rather than a fallback that starts something which does not route `serve`. Every way a reach can end without a live socket — unresolvable bundle, a spawn that died on launch, a socket that answered a ping and then vanished — now surfaces as `RedskilledUnreachableError` carrying its cause, so an empty host state means an idle machine and never a failed lookup.
