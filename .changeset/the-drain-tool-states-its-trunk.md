The drain tool states its trunk, and the skills state their calls

**A registration without a trunk drains nothing.** The daemon states the Ticket
handoff only when every fact it requires is present, and `base` is one of them —
so the registration `rs_dev`'s `drain` composed birthed Workers that were never
briefed and idled. That was the hand-written mistake of the first live drain,
repeated by the product path. The tool now resolves the trunk from the
checkout's `origin/HEAD` (falling back to `main`) and carries it.

Beside it, the operating contract agents kept walking around is now spelled
out: `/afk` carries "The calls, in order" — `project_activation` → `drain` →
`status`/`events_since` → `project_stop` — and `/go` states what it never does
by hand: no worktrees, no branch pushed from the human's checkout, no CI
watched in a shell loop, no manual merge. An agent doing any of those is
rebuilding the deleted engine one shell command at a time; the repair is to fix
or file the MCP gap and dispatch again.
