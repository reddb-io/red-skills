Dispatch now refuses — or loudly names — a superseded engine. All three forensic recoveries on 2026-08-01 were the same shape: the fix merged, main went green, and every dispatched worker kept running the engine from before the fix, because nothing compared the engine about to run against the version the registry had published. Every dispatch surface (`/go`, `/go --scout`, and the MCP `worker_dispatch` shapes) now takes one reading before anything is minted or born: the resolved engine's build-info against the published dist-tag. Under the default `warn` policy a superseded engine dispatches loudly, naming both versions and the span of fixes it would forfeit; `plugins.dev.dispatch.engine_floor: refuse` makes it a hard stop that mints nothing and asks the host for nothing; `off` silences it. Two degrades keep the floor from becoming its own outage: an unreachable registry always warns and proceeds, so offline dispatch cannot die of the check, and a refusal is only ever taken on a FRESH registry read — a replayed record, an installed plugin, or a cached bundle is the newest version this host knows about, not the newest published, and can only warn. A source checkout or prerelease is never floored.
