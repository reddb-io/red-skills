# 0138 — Base freshness is a host fact: the grant names the fork point

Three residues of the old "every worker fends for itself" model survived ADR 0135's freshness redesign. Every Worker ran its own `git fetch origin main` against the shared repository — N workers, N concurrent fetches, and the field logs carry the signatures (`unable to lock ref`, `transient fetch failure`) of many hands maintaining one fact. A base that moved mid-run reddened green branches at the gate through their **generated** surfaces alone — a `chore(release): version packages` bump rewrites every package mirror — and the cure spent a bounded agent correction round on a fix that is fully deterministic. And a Worker learned the base had moved only at the gate, after the whole implementation, with no surface able to show the risk earlier. Separately, the daemon's log answered "what happened today" only by prose-reading, though the TOONL toolchain (`tq`, the streaming filter) can query typed records directly.

## Decisions

1. **The redskilled daemon is the only thing that fetches the trunk.** Refreshing the project's trunk mirror is part of admitting Workers — one single-flight fetch serves a whole admission burst, plus a background refresh on the poll cadence. Workers read the mirror; they never fetch the trunk themselves. Scope is deliberately the trunk only: per-worker branch fetches touch disjoint refs and stay worker-local until field evidence says otherwise.
2. **The admission grant names the fork SHA.** The daemon fetches, then hands the Worker its base SHA in the birth payload; the Worker forks exactly that commit. There is no window between fetch and fork, no ambiguity about which ref was read, and the fork point becomes an auditable part of the admission verdict — extending the ADR 0130 doctrine that no Worker exists without a judged admission to the question of *where it is born from*.
3. **An unreachable remote refuses the birth.** When the daemon cannot fetch at admission time, no Worker is born: the admission is refused with a named reason, the issue stays `ready-for-agent`, and the next producer cycle retries. Today this scenario births a full Worker only for it to fail and park as a transient — the refusal is the same fail-closed answer without spending a slot, an envelope, or budget.
4. **Generated drift heals mechanically, and the Verdict names the cure.** The operator declares the generated surfaces beside the Validation moments — path globs plus one regeneration command; no declaration, no mechanical cure, skipped loudly (the ADR 0135 shape). When a stale-base red's drift diff touches only declared generated paths, the Verdict's output names the mechanical cure — merge base, run the declared command, commit, re-validate, zero agent — drawing from the same bounded free stale-base cycles, one economy with a cheaper cure. A failed heal falls through to the existing agent correction round carrying the failure evidence. The Custodian's post-PR heal arm (ADR 0136) already covers ejections; this closes the pre-PR half.
5. **Base movement is stamped, minimally, and the log is a queryable record.** On each background refresh the daemon computes "base +N commits since the fork SHA" per live Worker and stamps it in host state; statusline and monitor render it, and the Verdict receives it as a ready environment fact. Every worker event in `redskilled.log.toonl` — birth with verdict and fork SHA, activity transitions, drift stamps, heals, deaths — is a typed record under a stable `kind` vocabulary, so `tq` answers "today's performance" as a query; the canonical recipes are documented beside the log contract. No new report verb and no separate metrics lane: the value is the stable shape, and the query engine already ships.

## Considered options

- **A project-side single-flight fetch broker** — rejected: a per-repo lock is exactly the many-hands maintenance being ended, and only the daemon knows an admission burst is happening.
- **A staleness stamp the Worker checks** (fetch time + SHA, refuse over a threshold) — rejected: it measures the fetch-to-fork window instead of closing it; the grant-carried SHA has no window.
- **Granting a stale SHA with a flag** when the remote is unreachable — rejected: it births a Worker whose first act is deciding whether it should exist.
- **Brokering every fetch through the daemon** — rejected: general-purpose git proxying is surface the field has not asked for; branch refs are naturally disjoint.
- **A pre-Verdict short-circuit for the mechanical heal** — rejected: a cure decided outside the truth function is the parallel-classifier pattern ADR 0136 exterminated; **a separate heal counter** — rejected: it would recreate the rival budgets just unified.
- **Rich collision telemetry** (intersecting base movement with the Worker's touched files) — deferred: it doubles the machinery for a hint; the minimal stamp rides free on the fetch the daemon already performs.
- **A separate metrics lane or a canned report verb** — rejected for now: a `tq` filter over one well-typed lane answers the same questions without a second writer, and a report surface can grow later on the same recipes.
