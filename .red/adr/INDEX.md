- **0130** `redskilled` is the host-scoped execution daemon; projects are its clients — every fleet is scoped to one directory, so each checkout spends the same host budget independently and nothing on the machine knows the total. One daemon per user session behind a unix socket owns worker process birth, death, limits, and placement across all projects, while the per-project bundle keeps owning the work; its contract is minimal and frozen (argv, placement target, budget, opaque project label, never repository layout), which dissolves rather than manages bundle-version skew across checkouts. Placement is a strategy per OS over a uniform floor — systemd transient units, Windows Job Objects, macOS rlimits — where the daemon's own RSS sampling guarantees the floor and a kernel backend upgrades precision, never existence. Workers are transient init-system units rather than daemon children, so the daemon restarts and re-attaches; it fails closed, auto-spawns with an optional supervising user unit, and persists only an append-only host event lane. A session reads the whole host and writes only its own project, and the MCP serves the statusline as both a rendered string and its payload. **Extinguishes the Fleet** (amends 0120's tool surface) **and the Attempt** (supersedes 0128 — since ADR 0103 made a retry a fresh Worker, a Worker already is one worker × one ticket × one try, and liveness re-anchors onto the daemon, which owns process death by construction); re-anchors 0129's Re-seed budget and the janitor's reclaim rule onto the Worker; amends 0113's render seam (statusline render moves from dev to the MCP, reversing the letter to serve the intent); retires cross-host `federated-fleet-view`. Archiving 0128 and removing the attempt implementation are curation of a live decision and route through a Spec per 0127. **Amendment 2 (#2853)**: the host-scoped home `~/.red/redskilled/` belongs to the daemon — `provisionRedskilledHome` is its one creator, ADR 0067's sole-creator authority is explicitly repository-scoped, and `/red-setup` provisions by calling the owner (`redskilled provision`, idempotent) and offering the optional supervising unit, with `/red-doctor` reporting the same four checks read-only. **Amendment 3 (#2885)**: the scope is the **machine**, not the user session — `XDG_RUNTIME_DIR` is per user rather than per login, so the old wording described one daemon per user by accident; the case it never covered, two OS users on one machine, is now decided in code by a world-readable machine claim in a shared sticky directory, which refuses the second user by name (pid, uid, socket) rather than serving them from the first user's daemon or widening the socket. - **0127** The ADR editor is totipotent — the maintainer decides, the skill executes. `/adr-editor` (renamed from the ADR 0112 skill) supports every operation over `.red/adr/` as a first-class in-session verb: list, group by subject, surface inconsistencies, add, remove, rewrite (including `## Decision`), merge, split, archive, renumber, re-index. - **0113** Castle owns the truth, dev owns the host boundary — the ADR 0101/0102 split is sharpened from a list into a principle: castle owns execution state, policy, and the feeds computed from them; dev owns everything that renders that truth to a human or enforces it in a specific agent host. Expected to resolve #2237/#2250/#2252 without re-litigating the seam.
- **0114** CLI argument parsing is one contract, two implementations — red-castle is vendored and decoupled from `packages/shared` (it parses via `@effect/cli` + `@standard-schema/spec`), so #2248's "one parsing contract" cannot mean shared parser code castle imports (that strands the upstream, ADR 0101). ## Archived

Retired records live in `.red/adr/archive/` (ADR **0112**). Archiving is a
`git mv`, never a delete — the lane is **append-only** and CI fails if any file
in it disappears. Every archived number stays documented as a bullet in this
section, so the governance bijection
`Set(active ∪ archived numbers) === Set(INDEX numbers)` holds.

Each archived record must carry, in its `## Status` section, one terminal
status — `superseded`, `deprecated`, or `inert` — plus a successor pointer line:

```
superseded-by: 0113
```

`superseded` and `deprecated` records must name at least one successor ADR
number; only an `inert` record (shipped and no longer guidance) may write
`superseded-by: none (inert)`.

- **0107** Engine relocation migrates by waves and proves drain before deletion — *superseded by **0124***.
