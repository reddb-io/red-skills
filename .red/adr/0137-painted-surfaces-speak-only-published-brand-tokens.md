# 0137 — Painted surfaces speak only published brand tokens

The repo paints three surfaces — the dev statusline, the VS Code extension dashboard, and the herdr plugin panes — and none of them speaks the brand. The statusline's style module carried thirteen hand-tuned truecolor constants (wine backgrounds, rose keys, functional green/red/yellow) of which not one value matches a token in `reddb-io/brand`'s `tokens.json`; the other two surfaces delegate everything to the user's theme and so express no brand identity at all. Meanwhile the brand deliberately publishes **no** feedback colors — success/warning/danger are an explicitly unmade decision — so every green "healthy" and yellow "current stage" in the statusline was semantics invented in the brand's name. There was no mechanism on either side: brand changes reached no consumer, and any hotfix hex landed unchallenged.

## Decisions

1. **Compliance is strict: a painted surface emits only values published in the brand's `tokens.json`.** Emitting *no* value is also compliant — the terminal-default foreground, a VS Code `ThemeColor`, and a named ANSI slot resolved by the user's theme put no brand-foreign value on screen. What is banned is a hand-tuned literal.
2. **The glyph is the truth and `red.500` is the only spotlight.** State (health, current stage, attention) always survives in characters — the NO_COLOR/plain render is the semantic baseline, color never carries meaning alone. The published brand accent marks only "look here"; everything else is the neutral ramp read as intensity (current = brightest, recessed = darkest). Functional green/yellow die until the brand publishes feedback tokens; when it does, the derivation picks them up as ordinary published values.
3. **The mark's own treatment appears exactly where identity is the subject.** The statusline's leading block becomes the brand field — `brand.primary` background, `brand.on-primary` ink — with the second block receding to `neutral.900`/paper; the transparent zone is a neutral hierarchy (`paper` keys, `neutral.400` soft, `neutral.500` dim, terminal-default values); the lifecycle bar is a pure intensity ramp. On the theme-relative surfaces the same split holds: identity moments (dashboard header, brand field) paint truecolor from the package, functional chrome stays in the user's theme slots under the same grammar.
4. **The vendored `tokens.json` is the source, not a reference.** `packages/brand-tokens/` vendors the brand's DTCG file with `.upstream`-style provenance (recorded brand SHA), parses it at module load, resolves aliases, and derives the ANSI/CSS forms consumers paint with. The hand-written color constants are deleted, not annotated — a value that cannot be expressed as a token name does not ship. An npm dependency was impossible (the brand package is private, distributed as a tarball), which is why the copy is vendored.
5. **Freshness is a watch workflow, in the `red-upstream-watch` mold.** A workflow compares the recorded brand SHA against `reddb-io/brand` HEAD and opens an issue on divergence; the refresh is an ordinary ticket the autonomous lane drains. Drift becomes work, never a silent lag.
6. **A ratchet holds the extinction.** A repo-invariant test sweeps the painted surfaces — the three painted apps and the shared `redskilled-render` package, whose palette every one of them speaks — and fails on any literal truecolor escape (`38;2`/`48;2`) outside the brand-tokens derivation module — the deletion of the hand-tuned palette is held, not just performed.

## Considered options

- **Zoned compliance** (identity strict, functional colors pragmatic) — rejected: it preserves green/yellow semantics the brand explicitly has not decided, indefinitely, under a "temporary" label.
- **Tokens as anchors with documented terminal-tuned derivations** — rejected: every derivation is a hand-tuned literal with a citation, which is the drift this ADR exists to end.
- **Constants annotated with token names plus a value-allowlist guard** — rejected: two places for one truth; the guard would police a transcription instead of deleting it.
- **A brand-red progress bar** (`red.500` fill) — rejected: the bar is rhythm, not a call for attention; it would make the one spotlight ambiguous.
- **Truecolor everywhere on the theme-relative surfaces** — rejected: the VS Code status bar API cannot take arbitrary color, and painting over the user's terminal/editor theme in functional chrome buys identity at the cost of legibility the themes already solved.
